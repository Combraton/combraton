# Development entrypoint

The canonical operating agreement is [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). This pointer replaces the initial bootstrap plan so there is one development sequence.

Use current Claude Code/Codex and ordinary GitHub workflows to ship usable v0.1 releases of Combraton, PIO, CBR and Protocol. **Self-development is deferred until after those releases**, then considered through a separate dogfooding decision.

Start with [the documentation map](docs/README.md), [architecture handoff](docs/architecture/HANDOFF.md), and [verification](docs/VERIFICATION.md). The repositories currently contain specifications and development infrastructure, not product runtimes. Stack choices and exact contracts require the bounded experiments in the development guide.
